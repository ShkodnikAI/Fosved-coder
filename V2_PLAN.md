# FOSVED CODER V2.0 — План реализации

## Архитектурные принципы

### 1. Паттерн «Прокладка» (Middleware)
Модель НЕ знает о существовании инструментов. Ассистент молча:
- Подставляет содержимое файлов в контекст (prompt_injector)
- Извлекает команды записи/чтения из ответа (response_parser)
- Выполняет их, пользователь видит только итог

### 2. Двойной режим
- **Tool Calling** — для моделей с нативной поддержкой (Claude, GPT, Gemini)
- **Prompt Injection** — универсальный fallback для всех остальных (Qwen, Llama, Ollama)

### 3. Разделение экранов
- **Главный экран** — творческое обсуждение, скиллы, промпт-драфты, анкета
- **Экран проекта** — код, инструменты, git, файловое дерево

## Фаза 5: Семантический анализ кода (CodeGraph)

> **Статус**: исследование завершено, интеграция отложена до Слоя 3+.
> Оригинал: https://github.com/colbymchenry/codegraph

### Что такое CodeGraph

Локальная система семантического анализа кода, строящая граф знаний из кодовой базы
с помощью tree-sitter AST. Хранит всё в SQLite (`<project>/.codegraph/codegraph.db`).
100% локально, никаких API-ключей.

**Метрики**: −35% стоимости, −57% токенов, −46% время, −71% tool calls (бенчмарк на 7 OSS-репо).

### Ключевые возможности

- **19+ языков**: Python, TypeScript, JavaScript, Go, Rust, Java, C#, PHP, Ruby, C/C++, Swift, Kotlin, Scala, Dart, Svelte, Vue, Lua и др.
- **Граф вызовов**: callers, callees, impact analysis, trace между символами
- **FTS5 полнотекстовый поиск** по именам, сигнатурам, докстрингам
- **Framework-aware**: распознаёт роуты FastAPI, Django, Express, NestJS, Laravel, Rails и ещё 14 фреймворков
- **MCP-сервер** (10 инструментов через stdio)
- **CLI** + **TypeScript API**
- **14+ framework-specific resolvers** для динамического диспатчинга

### Почему отложено

1. **Разные языки стеков**: fosved-coder = Python (FastAPI), CodeGraph = TypeScript/Node.js.
   Интеграция только через subprocess (CLI) или MCP stdio.
2. **Дополнительный Node.js runtime** в деплое — усложняет Docker/развертывание.
3. **Текущий `context_manager.py` не является узким местом** — он примитивен, но рабочий.
   Основная ценность fosved-coder — AI-агент с tool calling, глубина контекста вторична.
4. **WASM tree-sitter** требует Node 20–24 (заблокирован на 25 из-за бага V8).

### Предлагаемый вариант интеграции (когда придёт время)

**CodeGraph как дополнительный tool для AI-агента** (не замена `context_manager.py`):

```
codegraph context <task>       — построить семантический контекст для задачи
codegraph callers <symbol>     — кто вызывает символ
codegraph callees <symbol>     — что вызывает символ
codegraph impact <symbol>      — радиус влияния изменения
codegraph affected <files...>  — какие тесты затронуты
codegraph trace <A> <B>        — как A достигает B через вызовы
```

Реализация: subprocess-вызовы `codegraph` CLI из `core/executor.py`,
результат передаётся агенту как контекст. Альтернатива — MCP-клиент на Python.

## Фаза 6: Умная система памяти (Smart Memory) — РЕАЛИЗОВАНА

> **Статус**: полностью реализована (2026-05-28, коммит `7c2cd5a`, merge `464b66c`).
> Оригинал: https://github.com/rohitg00/agentmemory

### Что изучено: agentmemory

Движок персистентной памяти для AI-кодинг агентов (18.7K ★, Apache-2.0).
Захватывает действия агента через 12 хуков, сжимает в векторизуемые факты,
инжектит релевантный контекст при старте сессии.

**Метрики**: 95.2% R@5 на LongMemEval-S (ICLR 2025), ~170K токенов/год
против ~19.5M при paste-full-context (−99% токенов).

### Ключевые идеи, применимые к fosved-coder

**1. 4-уровневая консолидация памяти (аналог человеческой)**

| Уровень | Что хранится | Аналог |
|---------|-------------|--------|
| Working | Сырые tool-outputs текущей сессии | Краткосрочная память |
| Episodic | Сжатые саммари сессий | «Что произошло» |
| Semantic | Извлечённые факты и паттерны | «Что я знаю» |
| Procedural | Рабочие процессы и решения | «Как я это делаю» |

**2. Гибридный поиск: BM25 + векторный + графовый**
- BM25 (ключевые слова) + cosine similarity (семантика) + knowledge graph (связи)
- Слитие через Reciprocal Rank Fusion (RRF, k=60)
- Реализация на Python: `rank_bm25` / `whoosh` + `sentence-transformers` + numpy
- Хранение: SQLite FTS5 для текста, in-memory numpy-массивы для векторов

**3. Не-деструктивная компрессия**
- Текущая реализация: `DELETE` старых сообщений после LLM-сжатия — данные теряются навсегда.
- Целевая: помечать `archived=True`, хранить полную историю для поиска,
  в LLM-контекст инжектить только сжатое саммари.

**4. Project profile (профиль проекта)**
- При первом обращении собрать ключевые концепции, используемые файлы, паттерны.
- Кэшировать в `repo_maps` (таблица уже существует в БД).
- Инжектить при каждом запросе к проекту — аналог `memory_profile` из agentmemory.

**5. Автодедуп наблюдений**
- SHA-256 хеш tool_output с 5-минутным окном — защита от дублей.
- Применимо к `tool_usage_stats` (таблица уже есть).

**6. Memory decay (затухание)**
- Кривая Эббингауза: часто используемые факты усиливаются, редкие — затухают.
- Авто-эвикция неактуальных данных (retention policy).
- Полезно для long-lived проектов с сотнями сессий.

### Почему прямая интеграция невозможна

1. **Разные стеки**: agentmemory = TypeScript (ESM) + iii-engine (Rust/WASM),
   fosved-coder = Python 3.12 (FastAPI). Полная несовместимость.
2. **Дополнительный Node.js runtime** в деплое — отдельный сервис, оверхед.
3. **Разные БД/ORM**: agentmemory использует iii-engine StateModule (SQLite),
   fosved-coder — SQLAlchemy (PostgreSQL/SQLite).
4. **Хуки не применимы**: agentmemory захватывает действия через 12 хуков
   для Claude Code/Cursor; fosved-coder использует собственный WS-агент-луп.
5. **21,800 LOC TypeScript** — нереально поддерживать как зависимость в Python-проекте.

### Реализованная архитектура (2026-05-28)

```
core/
├── memory.py              # SQLAlchemy модели + CRUD (26 таблиц)
├── memory_embeddings.py   # Vector embeddings + RRF fusion (BLOB в SQLite/PG)
├── memory_decay.py        # Кривая Эббингауза + eviction loop
```

- `sqlite3 FTS5` / PostgreSQL `gin(to_tsvector)` — полнотекстовый поиск (встроен)
